# 办公 Agent 书稿编辑约定

更新日期：2026-11-08

## 定位与主线

以 [全书策划](BOOK_BRIEF.md) 的三篇十五章为当前架构：个人工作改善、组织共同能力、企业集团与时代变化。具体章名允许在写作中调整，核心观点发生变化时回到策划记录。

第 3 章样章获用户认可后，已按要求完成全篇。唯一主稿包含三篇十五章、阅读导引与两份附录；用户随后确认内容，第一版已调用 `build-ebook` 制作阅读版本。后续修订继续回到主稿。

## 作者与文风

用户已明确固定作者署名“李钊”、工作室与出版单位“若谷书房”，后续直接沿用，不再重复询问。作者的亲身经历和价值判断由用户提供或认领，不替用户虚构。

用自然、清楚的中文解释工作中的问题。以场景和推理带出方法，兼顾具体操作与组织视角。少用宣传口号、绝对化结论和技术名词堆叠；避免把每个章节写成检查表。没有证据时保留问题。

## 主稿与章节格式

- 唯一主稿为 `manuscript/book.md`，不另存一份并行维护的样章正文。
- 主稿以书名为一级标题，二级标题为“第 3 章 章节标题”这样的章节标题，三级标题为章节内的节。
- 尚未撰写的章节只记在策划与进度中，不用空标题填满主稿。
- 使用标准 Markdown 段落、平级列表、简单表格、链接与代码块。出版时再处理署名、封面和其他元数据。
- 个人实践章应交代问题、材料、任务、实际处理、成果、验收与适用条件，顺序可随叙述调整，不强求固定小标题。
- 组织章解释参与者、共同知识、执行能力、流程和责任；宏观章区分事实、机制判断和情景推演。

## 案例与来源

当前贯穿案例为“内部培训报名流程改进项目”，人物、事件和资料均为原创模拟，用于练习。不得将其表述为客户案例、用户经历或真实企业成效。

案例材料保留稳定标识，交付文件中的关键判断能回到相应记录。来源台账存于 `sources.md`；原始材料、作者推论和工具输出分清。原文、统计和产品能力引用需核查，不编造测试结果。

本次使用能在本地读取、检查和写入文件的 Agent 完成案例。执行后的记录只描述实际发生的动作，不伪造产品截图、对话、失败过程或重试次数。模拟数据上的成功不作为一般可靠性或普遍提效的证明。

后续案例覆盖个人任务、团队共建、企业与集团协作。供应链和社会层可以采用明确的情景分析。避免相邻章节只更换人物和单位名称重复同一故事。

## 术语与论证

共享上下文指共同维护的事实来源、业务口径、任务状态和协作规则，并按角色与任务提供相关信息。模型提供理解、生成和推理等能力，算力支持运行；工具说明属于理解能力所需的信息，实际操作由可用工具和系统承接。

个人节省的时间、组织整体交付周期、业务价值与收益分配分别讨论，不把前者自动累加成后者。任何效率数字都要说明测量方法，并计入准备、核查和返工。

## 全篇写作与后续修订

组织篇写清参与者、知识、执行、协作、维护及评价机制；第三篇保留积极建设的视角，分别说明集团、经营生产战略、供应链、知识劳动价值与生活衔接。各章现有正文约 1700 至 2300 个中文字，以问题解释完整为准；后续不靠重复填补字数。

受委托的章节写作者只写各自获分配的 `drafts/ch05.md` 等输入文件，不能直接修改主稿。采用二级章节标题、三级节标题；章节编号为阿拉伯数字。来源与统一案例约定见 [来源台账](sources.md)。新增情境明确为说明例子或设计延展，不写成实际运行结果。

只有主编可以将输入归并到 `manuscript/book.md`。合并后删除临时章节输入，后续修改直接在主稿进行，避免出现两套正文。完成章节独立审阅，并统一删减重复、调整衔接。

## 本批验收

第 3 章建议约 2000 至 3000 中文字，不以字数替代内容。材料、任务和交付文件实际存在；状态冲突、负责人缺失和期限缺失被准确保留。首次结果若已合格，如实记录，无须安排虚构纠错。

第一篇第 1 至 4 章连续可读，各章职责清楚，不把聊天界面、工作流与 Agent 视为互不相容的产品类别。新增章节不虚构实际操作，不将复盘建议冒充已测量的提效结果。

全书需三篇十五章齐备，前后术语、证据性质和章节职责统一。组织篇不能停留于口号，须有可采用的设计例子；第三篇交代推演条件和参与者的行动，不能把个人演示外推为普遍社会效果。正式主稿不出现“待写”“待补”等占位内容。

样章与第一篇已完成独立章节审阅。后续协作因工具额度中断，主编接手续写并逐章审阅协作稿，完成全书证据边界、论证与连贯性修订；未另行完成的交叉审阅不记为已完成。修改事实、论证或案例时记录必要变更，不承诺机械的修订轮数。

章节结尾应从“我怎样完成任务”引出“团队怎样共同依赖知识和规则”，让第二篇从具体问题自然生长。第一版采用字体版式封面，正文不加装饰插图，制作与检查范围见 [QA.md](QA.md)。
